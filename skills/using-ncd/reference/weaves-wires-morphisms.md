## Why broadcasting is the point

Deep learning architectures are precisely defined mathematical functions, but they are
communicated through tensor notation, framework code and hand drawings, none of which is
one formal object. The missing piece, in the authors' view, is broadcasting: how an
operation is extended over additional axes. SoftMax is $\mathbb{R}^x \to \mathbb{R}^x$;
applied row-wise it becomes $\mathbb{R}^{nx} \to \mathbb{R}^{nx}$, and nothing in the
shape says which of $x$ and $n$ is the target and which is broadcast. A dot product
$\mathbb{R}^b \times \mathbb{R}^b \to \mathbb{R}$ broadcast over $a$ rows and $c$ columns
is matrix multiplication; batched and convolved matrix multiplications each have their
own shape. Kernels are tiled algorithms defined with respect to the broadcast axes, so
performance models follow from clearly defined broadcasting (as *FlashAttention on a
Napkin* derives FlashAttention procedurally). Category theory is used because
parallelisation is a composition property, and because a categorical description grants
a library of standard transformations: diagrams, hypergraphs, Para for backpropagation,
Stoch for randomness and quantisation, DP for co-design.

## Encoding mathematics: constructed terms

The framework separates the mathematical objects from the terms that represent them, so
that notation, diagrams and code all represent the same entities soundly.

**Mathematical entities.** A set $\Gamma$ of entities closed under finite products, with a
$K$-family of core properties $\pi_k : \Gamma_{k,i} \to \Gamma_{k,f}$.

**Constructed term system.** A set of terms $G$, closed under finite products, an
interpretation $V_G : G \to \Gamma$ (written $\llbracket g \rrbracket$), and for each
core property an internal counterpart $p_k$ satisfying internal evaluation $p_k ; V_G =
V_G ; \pi_k$: evaluating inside the term system agrees with evaluating the mathematics
after interpretation.

Two ways implement core properties:

- **Construction rules** (contravariant). A rule $T_c : G_{c,i} \to G_{c,f}$ is a wrapper
  that remembers its builder terms, with a native recovery $\hat T_c$ so that
  $\hat T_c ; T_c = \mathrm{Id}$ and interpretation $V = \hat T_c ; V_G ; \pi_c$. Think of
  "$3 + 2$": the rule is $+$ and the builders are $3$ and $2$. Compound rules compose and
  take products, and remain recoverable. Rules grant **axioms**: when two constructions
  yield the same result (associativity), an axiomatically unified term such as $x + y + z$
  may be used. Code rarely generates axioms; diagrams use them constantly.
- **Root terms** (covariant). Non-constructed terms grouped into root types, each storing
  the data from which its properties are extracted natively. **Templates** restrict the
  creation of that data to terms that correspond to an entity; **metadata** tags carry
  non-core information; **methods** derive non-constructed properties of constructed
  terms from their builders.

**Placeholder terms.** "$x + y + z$" denotes a construction pattern with three open
inputs. In notation they are free symbols; in code they are terms with UIDs. Substitution
$y := z$ is a meta-level rearrangement $[0, 1, 1]$. Scanning an expression for UID-tagged
terms generates its configuration space, which is how a polymorphic expression with
pending axis sizes becomes a concrete model.

## Categories

**Monoidal product category.** Objects with an associative product $\otimes$ and unit
$\mathbb{1}$; morphisms $f : A \to B$ with associative composition $;$ and identities;
products of morphisms $f \otimes g : A \otimes C \to B \otimes D$; bifunctoriality
$(f \otimes h);(g \otimes k) = (f;g) \otimes (h;k)$; the usual structural guarantees.

**Rearrangements.** Structural morphisms generated by finite remappings $\mu : J \to I$ on a
family of objects: $[\mu]_{(A_i)} : \prod_i A_i \to \prod_j A_{\mu(j)}$. Classified by
count: neutral (swap, each input once), increased (copy), decreased (delete). $[0,0]_X$
copies, $[1,0]$ swaps, $[\,]_X$ deletes. Identity remappings are always allowed and
natural; products and compositions of rearrangements are rearrangements. A natural
remapping slides past a product of morphisms: $(\prod_i f_i);[\mu]_{(B_i)} =
[\mu]_{(A_i)};(\prod_j f_{\mu(j)})$. Which rearrangements are allowed and which are natural
distinguishes systems: copying is natural in Set (copy the result, or copy the input and
run twice), not in Stoch (two dice are not one die copied), and not for the computational
cost or the architecture of a learned layer. Symmetric monoidal categories make swapping
natural and yield a graph (hypergraph) structure.

**Implementation.** Objects are flat tuples of lone objects (nested products are
isomorphic to flat ones). Product objects, composition, products of morphisms and blocks
are construction rules; root morphisms and rearrangements are root terms.

```python
class ProductObject[L]:                      # pyncd: cat.ProdObject
    content: Prod[L]
abstract class Morphism[L]:                  # cat.Morphism
    def dom() -> ProdObject[L]: ...
    def cod() -> ProdObject[L]: ...
class Composed[L, M: Morphism[L]](Morphism[L]):          # cat.Composed
    content: Prod[M]
    def dom(): return content[0].dom()
    def cod(): return content[-1].cod()
class ProductOfMorphisms[L, M: Morphism[L]](Morphism[L]):  # cat.ProductOfMorphisms
    content: Prod[M]
    def dom(): return ProdObject(concat(m.dom() for m in content))
    def cod(): return ProdObject(concat(m.cod() for m in content))
class Rearrangement[L](Morphism[L]):         # cat.Rearrangement
    mapping: Prod[int]
    _dom: Prod[L]
    def dom(): return ProdObject(_dom)
    def cod(): return ProdObject(_dom[mu_j] for mu_j in self.mapping)
class Block[L, M: Morphism[L]](Morphism[L]):  # cat.Block, with BlockTag(repetition, aesthetics)
    body: M
    block_tag: BlockTag = BlockTag()

type ProductCategory[L, M: Morphism[L]] = (
    M | Rearrangement[L] | Composed[L, ProductCategory[L, M]]
    | Block[L, ProductCategory[L, M]] | ProductOfMorphisms[L, ProductCategory[L, M]])
```

In diagrams: objects are arrowed wires, composition is horizontal placement, products are
vertical stacking separated by dashed wires, a rearrangement is wires crossing, merging or
ending, and a block is a backdrop. Bifunctoriality is enforced axiomatically by the
drawing.

## The array-broadcasted category

**Indexing category.** A symmetric monoidal product category whose lone objects have
finitely many totally ordered elements $\mathrm{El}(P) = \mathcal{I}(\mathbb{1}, P)$ and
whose morphisms are determined by their action on elements.

**Canonical forms and synthetic objects.** Isomorphic objects may be collapsed to one
canonical form without loss, and conversely new object symbols isomorphic to existing
ones may be introduced; composition is then natively restricted until the isomorphisms
are applied.

**Monoidal array category** $[\mathcal{C}; \mathcal{I}]$. Arrays $[X; P]$ are synthetic
objects isomorphic to $\prod_{p \in |\mathrm{El}(P)|} X$ through the join
$\mathrm{Jn}(X, P)$ and separator $\mathrm{Sp}(X, P)$. Arrays are reannotations of
existing products; no new mathematics is introduced, only a language for parallel
structure that applies to any symmetric monoidal base.

**Batch lift and reindexing.** For $f : X \to Y$ and $P$, the batch lift is
$[f; P] = \mathrm{Sp} ; \prod_p f ; \mathrm{Jn} : [X;P] \to [Y;P]$. For $\eta : P \to Q$
in $\mathcal{I}$, the reindexing is $[X; \eta] = \mathrm{Sp} ; [\eta] ; \mathrm{Jn} :
[X;Q] \to [X;P]$. Note the reversal: a reindexing maps output indices to input indices,
against the data flow, which is why tsncd draws a reindexing with its codomain on the
left.

**Lemma (compositionality).** $[f;g\,;P] = [f;P];[g;P]$ and $[X; \rho;\eta] =
[X;\eta];[X;\rho]$. When $\eta$ is natural in the base or $f$ is deterministic (natural
for every rearrangement), $[f;Q];[Y;\eta] = [X;\eta];[f;P]$: the Yoneda-like sliding of
a reindexing through a lifted operation. Dropout is the standing counterexample: a repeat
does not slide through a random operation.

**Canonical forms used by diagrams and code.** $[[X;P];Q] \mapsto [X; Q \otimes P]$ (each
new wire on top), $X \mapsto [X; \mathbb{1}]$, and $[\prod_i X_i; P] \mapsto \prod_i
[X_i; P]$ (products distinguished by a dashed wire). A batch lift is a wire placed over
an expression; a reindexing is a hexagon on the relevant wires.

**Weaves and integrated reindexings.** Writing a row-wise operation as a lift beside
separate stride transformations is mathematically clear but misses what is computed and
is not concise, so the indexing information is integrated into the morphism. A **weave**
tags each position of an indexing object as front (tiled) or back (target). A broadcasted
operation has a target morphism $f$, a degree $P$, codomain weaves with front length
$|P|$, one reindexing $\eta_i : P \to Q_i$ per input, and domain weaves with front length
$|Q_i|$:

```python
class Weave[B, A]:  # cat.Weave(datatype, _shape)
    base: B
    shape: Prod[A | TILED]  # cat.WeaveMode.TILED

    def impose(tiling):
        return Array(
            base, ProductObject(next(tiling) if a == TILED else a for a in shape)
        )


class Broadcasted[B, A, S: Morphism[A]](Morphism[Array[B, A]]):  # cat.Broadcasted
    target_operation: Operator  # operator
    dom_weaves: Prod[Weave[B, A]]  # input_weaves
    cod_weaves: Prod[Weave[B, A]]  # output_weaves
    reindexings: Prod[ProductCategory[S]]  # reindexings, one per input

    def dom():
        return ProductObject(w.impose(r.cod) for w, r in zip(dom_weaves, reindexings))

    def degree():
        return allequals(r.dom for r in reindexings)

    def cod():
        return ProductObject(w.impose(degree()) for w in cod_weaves)
```

Mathematically $B = (\prod_i [X_i; (\eta_i \otimes \mathrm{Id}) ; [\sigma^{-1}_{d_i}]]) ;
[f; P] ; (\prod_j [Y_j; [\sigma_{c_j}]])$, where $\sigma_w$ is the symmetric map a weave
encodes. The paper notes that the same mathematics may vary computationally, which the
Alg layer below captures.

## Imposing structure: BorelStoch, affine indexing, Para, Alg

- **Base category $\mathcal{B}$ = BorelStoch.** Objects are standard Borel spaces,
  decomposable into lone objects isomorphic to $\mathbb{R}$, $\mathbb{Z}$ or a finite set
  $n$; morphisms are Markov kernels, with deterministic functions as Dirac kernels;
  composition integrates. Implementations do not define these maps: operator tags name
  the operation and metadata lets a backend evaluate it.
- **Indexing category $\mathcal{A}$.** Axes with elements $\{0, \dots, |P|-1\}$; morphisms
  are finite affine maps $\eta(\mathbf{x}) = \Lambda_\eta \mathbf{x} + v_\eta$ with
  composition $\Lambda_{\eta;\rho} = \Lambda_\rho \Lambda_\eta$, $v_{\eta;\rho} = v_\rho +
  \Lambda_\rho v_\eta$. (pyncd's `StrideMorphism`. The paper restricts images to the
  codomain; the implementation instead lets an out-of-range read yield the universal unit,
  which is how causality and padding are written.)
- **$\mathbf{Para}$.** A morphism $\langle \theta, f \rangle : X \to Y$ is $f : \theta
  \otimes X \to Y$; composition accumulates hidden parameter objects into a tape, so
  learned layers compose without their weights disturbing the wiring. pyncd's
  `para/` package: `Grab`, `Drop`, `TapeSlot`, `ParaWrap`.
- **$\mathbf{Alg}$.** An algorithmic layer over $\mathbf{Para}([\mathcal{B};\mathcal{A}])$
  related by a functor $F$. Two algorithmic terms may differ while $F(f_0) = F(f_1)$,
  written $f_0 \equiv f_1$: a transpose and its inverse do not cancel in Alg, a pure
  product $f \otimes f$ differs from a lift $[f; P]$, and a quantised datatype is
  $\mathbb{R}$ with a tag. Optimising an implementation is exploring mathematically
  equivalent, algorithmically distinct expressions.

## Key operations

- **Operator tags** are pictograms: an expanding triangle for SoftMax, a chipped bold
  rectangle $\mathbf{L}$ for a learned linear layer, a bold circle holding a pictogram
  for a norm (a V for RMSNorm), a lightning bolt for dropout, $\mathbf{E}$ for an
  embedding. Each is polymorphic over axis sizes and is configured through the UID logic.
- **Broadcasting as slices.** When the base supports natural deletion, broadcasting
  corresponds to translating slices $[i, :]$ over the broadcast axis; a slice is the
  reindexing $[X; i \otimes \mathrm{Id}_Q]$.
- **Einstein operations.** A reindexing on an identity gives transposes, diagonalisations
  ($\mathbf{y}[p, :] = \mathbf{x}[p, p, :]$, the remapping $p \mapsto (p, p)$) and
  repetitions ($p \mapsto ()$). A terminating dashed line is multiplication, so
  independent reindexings give an outer product; a terminating wire is a sum, and a
  diagonalisation followed by a sum is a curved cup, the inner product. The query-key
  product `'q h d, x h d -> h q x'` is weaved multiplication followed by summation, with
  heads expressed by broadcasting.
- **Dropout.** A Markov kernel $\lightning(r) : X \to X$, elementwise, so every axis is
  tiled and the glyph hovers over the wires. Repetition is a count-increasing remapping,
  and dropout is non-deterministic, so repeat-then-dropout differs from
  dropout-then-repeat: index sliding fails exactly where the algebra says it must.
- **Learned operations.** Para hides the weight input; the layer is bold. Multidimensional
  linear layers are stated directly, where PyTorch needs exogenous reshapes.
- **Embeddings.** $\mathbf{E} : V \to [\mathbb{R}; m]$ with $V \in \mathbb{N}$; the integer
  datatype is drawn as an arrowed wire, and a $V$-sized datatype against a $V$-sized axis
  overrides the cup as a selection.
- **Mixture of experts.** Per-expert linear layers carry an extra $n$ input like an
  embedding; a Top-K produces $k$ weights and chosen indices $[n; k]$; each token runs its
  $k$ experts in parallel and sums over normalised weights. A mathematically simplified
  form moves the $k$ selection to the outputs over a sparse axis $k/n$; evaluating it
  needs the hypergraph tools to rewrite it back.
- **Convolution.** $\mathbf{y}[i_{\bar x'}, :] = \sum_{j_k} \mathbf{L}[j_k] \cdot
  \mathbf{x}[i_{\bar x'} + j_k, :]$ splits into the reindexing $+ : \bar x' k \to \bar x$
  (the convolution matrix, which is affine and therefore computationally distinct from a
  general matrix) followed by a $kc \to c'$ linear layer. Translation equivariance follows
  by sliding a shift $i \mapsto i + t$ through the expression.

## What the implementation adds

- **Interoperable packages.** The Python package follows the term-construction framework
  and the pseudocode; the TypeScript package mirrors the data structure and renders.
  Expressions are JSON between them.
- **Autoalignment.** `@` finds functors $F_f : Y_f \mapsto Y$ and $F_g : Y_g \mapsto Y$
  so that $f @ g = F_f(f) ; F_g(g)$. Procedure: if the axis counts of the top segment
  mismatch, batch-lift the shorter expression; if the segment counts mismatch, take the
  product with an identity; then put corresponding axes into UID buckets with a canonical
  form applied over both expressions. Axes of separately written templates become equal
  only when a composition aligns them; axes that never meet stay distinct (two `d`s in
  attention).
- **Configuration generation.** The remaining UIDs are the degrees of freedom; an
  assignment sets them to desired sizes, making the expression ready to compile.
- **Compilation to PyTorch.** `Composed` becomes sequential modules, `ProductOfMorphisms`
  parallel modules, and a `Broadcasted` supplies its operator tag, weaves and reindexings
  as execution metadata. Nothing in the algebra is PyTorch-specific; any backend would be
  built the same way.
- **Hypergraphs.** Bifunctoriality and symmetry make the composed-product form redundant;
  converting `ProdCategory[L, M]` to `Hypergraph[L, M]` from first principles enables
  general rewrites (associativity, bifunctoriality, symmetry) on any symmetric monoidal
  category, including $\mathbf{Para}[\mathcal{B}; \mathcal{A}]$.
- **Diagram generation.** `Composed` becomes horizontally placed boxes,
  `ProductOfMorphisms` vertically placed ones; objects become sequences of anchors linked
  in turn. The renderer for categories in general is specialised to the broadcasted
  category.
- **Future work named by the paper.** Automatic kernel derivation in the manner of
  FlashAttention on a Napkin, algebraic backpropagation through Para, quantisation error
  composition, a diagrammatic model editor, and integration with categorical co-design.
